// the two halves

CI and CD are two different jobs

They're usually said in one breath, but they solve different problems — one keeps code correct, the other keeps it moving.

Continuous integration

Every time someone pushes code, it's automatically built and tested against everyone else's changes. The goal is to catch breakage within minutes, not weeks later.

  • Merges code frequently, in small batches
  • Runs an automated build on every push
  • Runs the test suite to catch regressions early
  • Fails fast and loudly, not silently

Continuous delivery / deployment

Once code has passed CI, it's automatically packaged and pushed toward production — either staged for a one-click release (delivery) or shipped straight through (deployment).

  • Packages the build into a deployable artifact
  • Promotes it through environments (dev → staging → prod)
  • Delivery: a human approves the final release
  • Deployment: passing the pipeline is the approval
// the pipeline

What actually happens, stage by stage

A pipeline is just automation glued together in order. Each stage only runs if the one before it passed.

01

Commit

A developer pushes code to a shared repository, triggering the pipeline via a webhook.

02

Build

Source code is compiled or bundled into a runnable form — often a Docker image.

03

Test

Unit, integration, and sometimes security scans run automatically against the build.

04

Release

A versioned, tested artifact is pushed to a registry, ready to be deployed.

05

Deploy

The artifact is rolled out to an environment — staging first, then production.

06

Monitor

Logs and metrics confirm the release is healthy, or trigger a rollback if it isn't.

// why bother

What this buys you

Faster feedback

A broken build is caught in minutes, while the change is still fresh in the developer's head.

Smaller, safer changes

Frequent small releases are easier to reason about — and easier to roll back — than rare big ones.

Consistency

The same automated steps run every time, removing manual, error-prone release rituals.

Confidence to ship

When tests and deploys are automated, shipping stops being a special, nerve-wracking event.

// common tools

What tends to show up in a real pipeline

These aren't mandatory, but they're the usual cast of characters.

CI/CD server

Jenkins, GitHub Actions, GitLab CI

Orchestrates the pipeline — watches for commits and runs each stage in order.

Packaging

Docker

Bundles the app and its dependencies into one portable image.

Infra

Terraform, Kubernetes, AWS

Defines and runs the environment the artifact actually deploys into.
